# Pangram → Opus 5.5: одиночная калибровка с опытом pairwise judge

Рабочий промпт заменён результатом описанной процедуры калибровки. Промпт и runtime выбраны по обучению и раннему dev до просмотра результатов нового теста. Разметка свежих текстов не передавалась селектору. Метрика измеряет имитацию Pangram, а не достоверность определения авторства или литературное качество.

## Что использовано из прежней калибровки

Найден локальный Opus 5.5 judge в `cmp/common.py`, `cmp/calib.py`, с результатами `cmp/out/calib_report.json`. Его rulebook точно совпадает с [miqdadbadjuber/anti-slop, commit 388cbe3](https://github.com/miqdadbadjuber/anti-slop/blob/388cbe3b6c37d5175b9f460015bb092ef9e34894/skills/antislop-copywriting/SKILL.md). Снимок, SHA-256 и MIT license сохранены в `round3/reference*`.

В исходной проверке: pairwise human-win 96,7% для обычного AI и 87,8% для humanlike AI; порядок устойчив в 44/45 и 42/45 парах. AUROC 0,993/0,941 относится к отдельной абсолютной шкале human, а не к парному сравнению. Исходные фрагменты имели 90–300 слов. Эти результаты не доказывают совпадение с Pangram или работу на сверхкоротких текстах.

Отдельный вызов Opus 5.5 получил rulebook, отчёт и обучающие примеры и предложил три стратегии: контрфактическое сравнение формулировок, нормировку признаков по длине и исправленные жанровые правила. К ним добавлены пять пар с противоположными метками Pangram как фиксируемые в промпте примеры. Каждая пара происходит из одной исходной группы; все эти группы исключены из оцениваемого train и dev. Эти десять показанных примеров не входят в training score этапа Shinka. Новые парные оценки авторства не подменяют метки Pangram.

## Протокол поиска

Общий пул: 690 текстов. Прежний test раунда 2 теперь обучающий и больше не считается независимым. Подбор идёт на фиксированных 128 случаях, 64 на класс, с настоящими human-контролями и короткими положительными примерами. Support: 10 текстов из пяти отдельных групп. Предварительный выбор стартового промпта: 32 случая из train. Shinka: до восьми попыток поколений или до достижения потолка метрики на train, 4 оценённых вариантов. Во всех стадиях — один классифицируемый текст на API-запрос, включая поиск; показанные размеченные reference-пары являются частью самого промпта.

Критерий: 50% общей balanced accuracy + 50% средней balanced accuracy диапазонов длины, где есть оба класса. Отказ провайдера считается ошибкой, а не меткой human; случаи не исключаются. Dev из 105 текстов используется повторно, поэтому не считается новой независимой оценкой. По dev выбирается между прежним промптом и лучшим обучающим кандидатом; ни fresh-test тексты, ни метки не передавались оптимизатору.

## Ограниченный шаг по оставшимся ошибкам

Прежний dev был явно переведён в калибровочное обучение. Shinka получил 129 случаев: 105 бывших dev и 24 контрольных текстов вне reference-групп. Выполнена одна попытка мутации после baseline. Эти данные уже не являются независимой проверкой; итоговое качество измеряется только на новом test. Метки reference-примеров не менялись, отказы провайдера не оптимизировались.

## Использование и артефакты

`best_prompt.txt` — выбранные критерии и reference-примеры (если сохранены кандидатом); `inference_system.txt` — полный system с контрактом; `request_template.json` — точный API-запрос без ключа. Модель `anthropic/claude-opus-5.5`, strict JSON schema, выбранный на dev режим reasoning, max_tokens зависит от выбранного runtime, temperature не задаётся. Точные настройки находятся в request_template.json и inference_config.json. Один классифицируемый текст на запрос.

С `OPENROUTER_API_KEY` в окружении, из этой папки:

```sh
.venv/bin/python classify.py example.txt
```

Или stdin. Ответ `{"slop": true}` / `{"slop": false}`. Отказ провайдера возвращает JSON-ошибку в stderr и код выхода 2.

Полные результаты: `round3/results.json`, `round3/test_results.json`, `round3/validation.json`, `round3/screen_results.json`, `round3/advisor.json`. Оригинальные ответы API и неудачная первая попытка консультанта сохранены отдельно. Исходные данные содержат provenance; условия Brown (некоммерческие исследования), Enron/Yelp и прочих корпусов сохраняют силу. Ключи не записываются в проект.

## Расходы за всю сессию

- openrouter: консервативно $57.40 из $100, включая запас и неизвестные резервы.
- pangram: консервативно $79.24 из $100, включая запас и неизвестные резервы.

Pangram — расчёт по тарифу за начатые 100 слов с запасом, не выписка счёта. OpenRouter — возвращённые стоимости с запасом и незакрытые резервы. `cache/budget.json` сохраняет общий лимит; не сбрасывайте его при продолжении.

Зависимости: `requirements-lock.txt`; Shinka commit `8adc053a2ce4511ad2ac310e004c530a73fb974a`. Скрипты полного раунда находятся в `round3/`. Предыдущий промпт, результаты и README сохранены с префиксом `round3/previous_`.

Повторяемость выбранного промпта: 8/8 заранее отобранных случаев дали одинаковый ответ в трёх вызовах; отсутствующих ответов: 0. Это малая диагностическая проверка, не гарантия детерминизма.

Операционный критерий приближения к Pangram: ПОКА НЕ ДОСТИГНУТ. Не пройдены: overall_balanced_accuracy, overall_agreement, pangram_human_recall, length:lt25, model:openai/gpt-5.5 Точные заранее записанные пороги — round3/goal_criteria.json; проверка — round3/goal_assessment.json.

Дополнительная dev-проверка runtime до просмотра fresh-outcomes: minimal / provider-default / medium с тем же промптом и строгой схемой. Выбран режим **default**. Кеширование system-prefix для default/medium настроено по [документации OpenRouter](https://openrouter.ai/docs/guides/best-practices/prompt-caching); reasoning — по [документации](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens). Это повторное использование dev, а не независимая оценка.

После runtime-проверки разрешены ещё два статических варианта: расширенные Pangram-примеры и полный исходный rulebook с расширенными примерами. Дополнительные примеры взяты только из train; они могут пересекаться с прежним оцениваемым train, поэтому исходный training score Shinka не относится к этим вариантам. Их выбор делался только на повторно используемом dev, до просмотра fresh-outcomes. Подробности — round3/anchor_validation.json.
