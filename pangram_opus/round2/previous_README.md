# Калибровка Pangram 4 → Opus 5.5

Промпт оптимизирован через Shinka Evolve и проверен отдельно. **Полная эквивалентность Pangram и универсальная устойчивость не подтверждены.** Главная слабость — ложные срабатывания на текстах, которым Pangram ставит Human Written.

Использованные модели: классификатор `anthropic/claude-opus-5.5`; учитель запрашивался как `pangram-4`, во всех 256 ответах фактическая версия — **4.1**. Бинарное правило: любой сегмент AI-Generated или AI-Assisted означает `slop=true`; только Human Written означает `false`.

## Результаты

| Проверка | Совпадение с Pangram |
|---|---:|
| Обучение, пакетный режим: исходный промпт | 83/97 — 85,6% |
| Обучение, пакетный режим: выбранный промпт | 91/97 — 93,8% |
| Отложенная выборка, одиночные запросы: исходный | 20/31 — 64,5% |
| Отложенная выборка, одиночные запросы: оптимизированный | 23/31 — 74,2% |
| Свежие генерации, 6 моделей × 4 режима × 4 задания | 96/96 |
| Legacy humanizer | 6/8 |
| Legacy Qwen-antislop, direct/rewrite | 16/16 |
| Rawmodels Antislop | 5/8 |
| Весь стресс-тест | 123/128 — 96,1% |

На основной отложенной выборке исправлены три ошибки исходного промпта, новых ошибок относительно него нет. Однако выборка мала: 95% Wilson-интервал для 23/31 составляет примерно 56,8–86,3%; точный парный тест McNemar даёт p=0,25. Это наблюдаемое улучшение, а не статистически убедительное доказательство общего превосходства.

**96,1% стресс-теста нельзя трактовать как универсальную точность.** Pangram пометил слопом 122/128 текстов, включая все 96 свежих генераций. Постоянный ответ «слоп» уже даёт 95,3%. У оптимизированного промпта TP=121, TN=2, FP=4, FN=1: balanced accuracy — **66,3%**, распознавание Pangram-Human Written — **2/6**. Для основной отложенной выборки Human Written recall — 11/16, slop recall — 12/15.

Повторяемость: **18/18 текстов получили одинаковые метки при трёх вызовах**. Набор включает по представителю каждой модели, все Pangram-negative стресс-примеры и четыре отложенные ошибки. Ошибочные решения тоже повторялись. Это диагностическая выборка сложных случаев, не оценка стабильности всей популяции.

## Модели и сценарии стресс-теста

Свежие генерации: GPT‑5.5, Claude Sonnet 5.5, Gemini 3.5 Flash, DeepSeek v4.1 Flash, Qwen3.6 Plus, Claude Opus 5.5. Для каждой модели использованы четыре задания — техническое объяснение, объявление, отзыв, художественная сцена — и четыре режима:

- Обычный ответ.
- Разговорный стиль с личным голосом.
- Антислоп-инструкции.
- Draft → critique → rewrite, все стадии одной моделью.

Дополнительно взяты фиксированные образцы существующих humanizer/Qwen-antislop/Rawmodels-пайплайнов проекта. Точные ревизии legacy-моделей полностью не подтверждены. Свежие ячейки содержат только по четыре связанных задания; нельзя экстраполировать 16/16 на все темы и модели. Длина стресс-текстов: 63–277 слов, язык — английский. Полные короткие ответы сохранены; обрезанные/пустые ответы повторялись с отключённым reasoning и увеличенным лимитом, до оценки детекторами.

## Использование

`inference_system.txt` — полный системный промпт с контрактом ответа. `best_prompt.txt` — оптимизированные критерии без фиксированного контракта. `request_template.json` — точное тело API-запроса без ключа. `results.json` — сводный отчёт; подробные метки находятся в `holdout_results.json` и `robustness/predictions.jsonl`.

Из этой папки, с `OPENROUTER_API_KEY` в окружении:

```sh
.venv/bin/python classify.py example.txt
```

Или подать текст через stdin. Ответ: `{"slop": true}` / `{"slop": false}`. CLI использует строгую JSON schema, `provider.require_parameters=true`, reasoning effort `minimal`, max_tokens 2048. Temperature не задаётся: модель не объявляет поддержку этого параметра. Шаблон API принимает JSON-массив объектов `id`, `text`; все финальные измерения делались по одному тексту за запрос.

## Воспроизводимость и бюджет

Shinka менял только строковый литерал PROMPT. Кандидаты проверялись AST-парсером и не исполнялись. Из 20 оценённых вариантов два не выдержали контракт JSON. Выбран `runs/batch1/gen_16/main.py` по training balanced accuracy; тестовые результаты не использовались для выбора или редактирования промпта.

Обучение и основная проверка разделены по исходным ID, чтобы оригинал и его AI-переписывания не разошлись между частями. Хеш-пересечения train/holdout/stress отсутствуют. Во время поиска использовались пакеты по восемь текстов. После фиксации промпта клиент переведён с JSON mode на строгую схему из-за ошибок формата; обе стороны финального сравнения проверены с одинаковыми новыми настройками. Промпт не менялся. Частичные результаты старого режима сохранены отдельно и не включены в итоговую метрику.

Оценка расходов: **OpenRouter ≈ $9,89**, **Pangram ≈ $28,95** по [опубликованному тарифу $0,05/100 слов](https://www.pangram.com/pricing). Pangram — расчётная сумма, не выписка счёта. Консервативный учёт с запасом и неизвестными резервами: OpenRouter $14,19; Pangram $65,80. Оба ниже разрешённых $100 на сервис. `cache/budget.json` включает расходы генерации, оптимизации, оценки и повторов; не удаляйте его во время продолжения эксперимента.

Ключей в файлах нет. `requirements-lock.txt` фиксирует зависимости; `manifest.json` — параметры и хеши исходных выборок. Проверены пять автоматических тестов, работа API, полный запуск Shinka, финальная классификация и отсутствие пересечений текстов.

Для воспроизведения экспериментальных этапов используются `prepare.py`, `run_evo.py`, `select_prompt.py`, `holdout.py`, `robustness.py` и `summarize.py`. `prepare.py` и `robustness.py label` требуют также `PANGRAM_API_KEY`. Сохранённый кэш предотвращает повторную оплату одинаковых запросов.
